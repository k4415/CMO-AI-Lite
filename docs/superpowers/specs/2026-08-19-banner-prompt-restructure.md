# 最終プロンプト再構成・配色自由度拡張・ライター入力増強（A/B/C）

- 日付: 2026-08-19
- 参照: Pro版 H-529 W契約（「重要情報を最初に」が実画像A/Bで最良判定）

## 診断（コード実測）

1. 実送信プロンプトは冒頭3,373字が契約文で、デザイン散文（3行ヘッダー）は42行目から始まる。Pro版は1文字目から3行ヘッダー。gpt-image-2は冒頭を重視するため、W契約の効果が減衰している
2. 配色ブロックが「この4色で構成する。palette外の色を主要色に使わない」と固定4色HEXへ締め付け、トーン・グラデーション・素材感の設計余地がない（ProのH-510/H-529で解消済みの症状と同型）
3. ライターへの戦略入力が3,000字クリップ（Proは12,000字）

## A. アセンブリ再構成（src/core/openai-image.js assembleWrittenBannerImagePrompt）

新しい順序: **散文 → 基本仕様（サイズ）＋基本指示（2行） → バナー内テキスト → 配色 → 契約ブロック（末尾）**

- 散文の先頭ラベル「【デザイン完成イメージ】」は廃止し、プロンプトが「形式：」から始まるようにする（clipWriterDesignBlocksのラベル扱いも追随）
- 現在headにある以下は末尾の契約ブロックへ移動: 閉構造契約（buildClosedStructureInstruction）、添付画像指示（buildAttachedImageInstruction）
- 「日本語のダイレクト広告バナー」「文字は生成時に一体配置・文字化け回避」の基本指示2行は散文直後に置く
- 契約ブロック内の重複文言を圧縮する（例: 選択素材関連はbuildAttachedImageInstructionとbuildFinalSelectedAssetInstructionで重複記述があれば1回に。各制約は1回だけ＝Pro H-476の作法）。目標: 契約ブロック合計を現行の約半分（1,700字程度）
- 予算計算（BANNER_IMAGE_PROMPT_BUDGET=12000、決定論ブロック先取り→残余を散文clip）は維持。決定論ブロックだけで超過時の空文字返却→レガシーfallbackも維持
- レガシー経路（assembleLegacyBannerImagePrompt）・リカバリプロンプトは変更しない
- テスト: 順序変更に伴うbanner-image-prompt-assembly.test.js等の更新。「散文がプロンプト先頭（形式：で始まる）」「契約が末尾に存在」「予算超過時の挙動不変」を固定

## B. 配色ブロックのW型化（formatWrittenBrandColorBoundary + config/prompts/banner-image-prompt-writer.md）

- 配色ブロック文言を変更:
  旧「ブランドカラー（この4色で構成する）: ... / 文字と背景のコントラストを必ず確保する。palette外の色を主要色に使わない。」
  新「カラーアンカー: {色リスト} / この色を起点に、トーン・グラデーション・素材感・光の演出はアンカー色から派生する範囲で展開してよい。文字と背景のコントラストを必ず確保する。アンカーと無関係な色を新たな主要色として導入しない。」
- writer mdの配色記述契約に追記: 「アンカー色からのトーン展開・素材感・商材を象徴する具体物のメタファー表現を設計してよい」（Pro W契約アンカー⑤相当）
- カラー契約assert（promptJson.colorScheme === colorDecision.palette）は不変。colorSchemeの値・検証は一切変えない（変えるのは散文プロンプト上の表現指示のみ）

## C. ライター入力増強（src/core/banner-image-prompt-writer.js + md）

- strategy markdownのクリップを3,000→12,000字へ
- ライター入力に creativeHypothesis（appealAxis / visualIntent 等の要点）を明示ブロックで追加（未入力なら省略）。既存の多様性方針ブロックは維持
- Pro E-1/W の設計指示との突き合わせで、mdに未移植の表現があれば補完する。参照文言（Pro原文・逐語）:
  - 色ルール: 「配色・トーンは次のように設計する。テンプレートからは色の役割構造（どの要素が濃色・誘目色・背景か）、コントラスト水準、トーンの感情だけを継承し、テンプレートの具体色は使わない。…（Liteでは具体色決定はコード側のため、使い分け設計と理由記述に読み替える）」
  - ヘッダー契約: 「image_prompt.promptは必ず次の3行の見出し付きヘッダーから書き始め、その後にレイアウトの記述へ進む。形式：…目的・戦略：…スタイル・トーン：…」（Lite実装済み・整合確認のみ）
- PIPELINE_POLICY_VERSIONS.prompt を 4→5（Cでライター入出力が変わるため既存バナーを再生成対象化）
